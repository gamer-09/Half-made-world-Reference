_This is the view-only archive hosted on GitHub Pages. It is generated automatically from `server/data/*.json` on every push, so it always reflects the latest committed world data._

## What you can do here

- Browse every entry by category, search, or tag.
- Open any entry to read its full description, fields, and connections.
- Explore the Relationship Map, Story Web, and Block Chain Map views.
- Export the whole archive as Markdown or JSON.

## What you can’t do here

This build is read-only. There are no add, edit, or delete controls — the “Add Entry”, “Add Relationship”, “Add Link”, edit, and delete buttons are removed from the view-only build. Keyboard shortcuts for adding entries are also disabled, and any attempt to use them shows a toast informing you that this is a view-only build.

## How it stays in sync with the world data

The deployed app loads a snapshot bundled at build time from these files:

- `server/data/world.json` — all entries
- `server/data/relationships.json` — character relationships
- `server/data/story-links.json` — story links

The build runs a prebuild step (`scripts/build-snapshot.mjs`) that combines those three files into `client/public/snapshot.json`, which the built app fetches as `/snapshot.json`. On pushes to `main`, GitHub Actions rebuilds the client from source and deploys the result to GitHub Pages, so the online archive always reflects the latest committed data in `server/data/`.

## Editing the world locally

To add, edit, or delete entries, relationships, and story links, run the project locally:

```
npm run dev
```

This starts both the Express server (which serves the live API on port 5001) and the Vite dev server. In local dev the full edit UI is available — the read-only gating only applies to the production build (`import.meta.env.PROD`).

To edit the underlying data directly, edit the JSON files in `server/data/` and restart the server. Edits made through the local dev UI are saved back to those same JSON files.

## Regenerating the snapshot locally

To see what the deployed snapshot will contain, regenerate it from the current server data:

```
npm run snapshot
```

This writes `client/public/snapshot.json` from the current `server/data/*.json`. The file is git-ignored because it is regenerated by the CI build on every push — do not commit it.

## Building for deployment

```
npm run build
```

This runs the snapshot prebuild step first, then builds the Vite production bundle into `client/dist/`. The `client/dist/` folder is what gets deployed to GitHub Pages. It is also git-ignored.

## Data format

Each entry in `server/data/world.json` is a JSON object with: `id`, `category`, `name`, `subtitle`, `description`, `fields` (array of `{label, value}`), `tags`, `createdAt`, `updatedAt`. Relationships and story links follow a similar shape with `source`, `target`, `type`, `label`, `description`, and optional `color`.
